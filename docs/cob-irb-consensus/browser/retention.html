Hard-coded rule: No files are to be deleted under any circumstances. Update, supersede, and archive with dated change notes so CoB IRB can always find prior materials.

Retention — update, do not delete

Why

IRB work depends on being able to reconstruct what was approved, when it changed, and what replaced it. Permanent deletion puts representatives in a position where they cannot find their materials.

Per-project Drive pattern

{protocol_id}/
  UPDATE_LOG.md          ← running log (append only)
  CURRENT/               ← latest files
  _archive/
    YYYY-MM-DD_label/
      CHANGE_NOTE.md     ← what changed, when, who
      …prior files…

Allowed vs forbidden

  • Allowed: add files; move old versions into `_archive/`; edit registry metadata; mark protocols archived (row retained); export dated registry snapshots.
  • Forbidden: Trash / permanent delete of CoB HSIRB Drive files; removing protocol rows from the registry JSON; emptying Drive Trash for these materials.

Registry tool

The protocol registry has no Delete control. Saves append a change_log entry. Export offers a current file and a dated snapshot for Drive 03_Protocol_Registry/_archive/.
